# Multi-seed development comparison of constant body step sizes

The campaign index reports a 200-task advantage for the 0.02 arm on seed 311011. The historical multi-seed scores for 0.02 and 0.005625 come from different cohorts. This experiment asks whether 0.02 consistently improves full-life pre-update accuracy when each arm sees the same sequence. It addresses the [open comparison](../../../docs/research/ipmnist-campaign-index.md#current-stored-record).

## Protocol fixed before execution

- Use the maintained v2 step-noise IPMNIST screening runner and registered arms `rls_head_resid_identmap50_r_idet003_s02_anneal_f1t1000_wd0` (candidate) and `rls_head_resid_identmap50_r_idet003_s005625_anneal_f1t1000_wd0` (control). Both use zero weight decay. Record resolved hyperparameters to check that the body step is the only intended mechanism change.
- Pair development seeds 311012, 311013 and 311014 across both arms, 200 tasks of 5,000 examples per run. These numbers follow the historical single seed. None appeared as a whole number in the campaign's tracked IPMNIST and local hillclimb artifacts at upstream commit `9fd70d6765f87637a5f24e08a96493c9e0ede514`. These development seeds may never support promotion.
- Run on CPU, Python 3.12, the locked research environment and the same canonical OpenML MNIST train bytes. Each arm gets a fresh process, with OMP, OpenBLAS and Accelerate thread controls set to one. Use the same clean protocol commit, runtime, dataset and settings throughout. Run arms sequentially, with the candidate first on the middle seed and the control first on the other two. Record separate process wall time, CPU time and peak RSS for all six shards. Shared-host timings are descriptive.
- The primary contrast is candidate minus control in mean per-task pre-update accuracy. A positive difference on all three seeds supports retaining 0.02 as the preferred development step at this horizon. Any tie or loss leaves consistency unresolved. Report every seed and their mean regardless of sign; a small positive difference is not a population confidence claim. Do not alter the horizon, seeds, or criterion in response to interim scores.
- Report four non-overlapping 50-task paired differences per seed to distinguish an early gain from one surviving late in the sequence. These are secondary descriptive metrics. Check the maintained merge and all shard byte bindings. Keep the complete six-run set and source identity together; an incomplete set does not answer the question.
- This is a permanently nonpromoting subsystem comparison. It cannot change the reference channel, establish scientific evidence, or determine the best step size outside the tested pair. A later registration or application to a continual-control consumer requires its own protocol and decision.
